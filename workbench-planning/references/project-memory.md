# 项目知识库与记忆流程

## 资料入库和证据

| 输入 | 操作 | 核对 |
| --- | --- | --- |
| 课程链接 | 保存课程名和原链接，能读到课程页面时保留章节和作业要求 | 登录后才能看的内容，请用户提供可导出的讲义或正文 |
| 课件与讲义 | 归入当前项目，标题使用课件名，提取可读正文 | 资料仅有封面或扫描图时说明缺少可读文字 |
| 外部平台导出的资料 | 用户提供可读正文或文件后导入当前项目，保留原文链接 | 当前版本不保证飞书等账户已接通，不把平台登录当作工作台已获读取授权 |
| 对话和 AI 回答 | 对话按项目保留供回看，用户选择有用的回复作为资料 | 区分引用、推断和用户已经确认的结论 |

## 归档一份资料

1. 核对所属项目。一个文件涉及多门课时，询问主要归属，或分别提取各项目相关段落并回指同一原始来源。
2. 建议「大类 / 项目 / 主题 / 资料类型」位置。主题可用课程章节或任务阶段，资料类型可用通知、讲义、课表、作业要求、项目笔记或复盘。优先使用现有名称。拿不准时保留为未分类，列出候选位置。
3. 建立资料条目。至少包括标题、出处、日期（如有）、适用对象和要点。提取行动项时另记成果、截止、已知执行时段。扫描页、残缺截图和无法访问的链接只标注当前可见信息。
4. 同源重复内容先列出已有条目供用户核对。若是补充公告，保留各自日期与适用范围，标注它补充或取代了哪一条。原件和编辑稿保留各自的名称与用途。
5. 给出归档预览和拟写入位置。确认后使用当前工具的归档入口。若只能对话，输出可复制的条目，由用户自行保存。

## 检索和回答

- 优先用用户明确指定的资料。用户未指定时，从当前项目里结合关键词、主题、资料类型和发布时间选取相关片段。只有确实属于同一项目、同一事项的资料才做合并。
- 每个关键期限、成果要求都要标明来源。能找到章、页、通知日期或原文短句时一并给出。现有目标和课表可作为上下文，AI 自己的建议标成建议。
- 报名截止、完成截止、考试日期和拟执行时段分别处理。两份资料冲突时，先看适用对象、版本及更正说明。明确属于同一事项且有正式更正时，可以建议采用更正日期，并展示依据。仍不明确时列出选项，等待用户确认。
- 查不到资料时，说明缺失的是哪份资料或哪个字段。继续推进时保留未知项；信息不足的期限、时段和要求留给用户核对。

## 跨对话续接

1. 从当前项目读取已确认目标和规则、保存的草稿、正式任务及完成进度。
2. 用户说「继续安排这门课」且已有草稿时，先给调整建议。检查最新课件是否提供了章节变化、作业要求或截止日期。
3. 已完成的任务用来判断前置条件。需要返工时说明依据并请用户确认。原时间表或草稿里的旧日期与新资料冲突时，列出两个来源供选择。
4. 回答中说明依据，标清哪些是已确认记录、哪些是新建议。生成和修改都先给预览，正式安排走工作台确认。

## 结果回存和交接

| 结果 | 存放或处理方式 |
| --- | --- |
| 通知、课件和原链接 | 放在对应主题的来源资料下，保留标题和原始出处 |
| AI 提炼和规则解读 | 先预览。确认后作为单独资料，附引用和适用范围 |
| 已确认目标、长期偏好和固定安排 | 使用项目现有目标、共用规则或时间表入口，确认后生效 |
| 拆解草稿和正式任务 | 分别进入草稿和正式排期，通过任务名称和日期回查对应资料 |
| 实耗、产出和复盘 | 按日期记录实耗，确认后的复盘可作为知识库资料供后续查询 |

换AI 工具时，可使用已导出的项目记忆或提供续接摘要。摘要包括当前项目、已确认规则及目标、资料出处、已有任务和状态、待确认事项。读完先核对项目和日期，再利用现有进度提出下一步。

## 示例｜旧讲义和补充通知

假设「产品设计课」里有《访谈讲义》写着周五交三条访谈摘要，随后《作业补充通知》把截止改到下周一；课表注明周五晚有固定课，项目进度显示访谈已结束。

1. 两份资料分别归到「课程 / 产品设计课 / 用户访谈 / 讲义」和「课程 / 产品设计课 / 用户访谈 / 通知」。
2. 说明摘要数量来自讲义，截止日有正式更正，建议以补充通知为准，等待确认更新。
3. 续接时保留已完成的访谈，只生成整理摘要和检查完成的待办预览，避开固定课程。
4. 做完后把实际时长和产出写入复盘。下次提问时，可以找回解释截止日的通知，也可以查到任务做到哪一步。

## 检查场景

同一项目的共用规则由用户维护一次。排期前查看规则、硬截止和固定时段，规则冲突时列出该项并请求选择。需要交接给其他 Agent 时，可以从工作台导出项目记忆 JSON。

复盘优先使用所选日期的实耗记录。同一任务跨日时分别记录每一天，不把累计值重复计入。下次排期参考当前项目近期已完成的同名或同类型任务，说明样本量，缺少数据时标为粗估。

- **重新进入项目后续接。** 先完成一项作业并保存草稿，重新打开工作台后说「继续安排这门课」。检查建议是否接着已有进度。
- **项目隔离。** 两门课程有同名作业，切换项目后再次要求拆解。检查资料、草稿及进度是否属于当前项目。
- **来源冲突。** 讲义和已确认规则给出不同截止日。检查答复是否引用出处，并停下来等用户选用。
- **可回看。** 开始排期前查看提供给模型的资料标题、项目完成数和保存的草稿数，确认它们与当前项目一致。

通过后记录脱敏的输入、实际结果和用户采纳情况。失败场景记录误判或缺失证据，以及修改后是否消失。
