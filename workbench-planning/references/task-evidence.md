# 功能、能力、任务与运行证据

用户要求解释项目如何实现、核对能力差距或演示整条流程时，先围绕同一个项目和同一组资料工作。

1. 明确期望成果或功能及重要性，再识别各项需要的能力。软件项目核对前端、后端、数据与测试是否涉及；其他项目按实际成果组织，不套用代码任务。
2. 根据相关差距用选择题核对能独立完成、需指导、没做过或不确定；区分用户自述与已提供作品证据。
3. 按「成果／功能 → 能力及证据 → 差距 → 必须补齐的任务 → 每日成果与日期」解释任务为何存在。优先达到已确认目标所必需的事项，时间不够时给出可取舍方案，不承诺所有功能都能在截止日前完成。
4. 工作台在能力回答后生成「目标功能→重要性→所需能力与回答→证据和差距→补齐事项」表。对应能力题必须是本轮回答，补齐事项必须是可选建议之一。用户勾选后确认，回答和对应表保存到项目能力档案并随差距归档。正式子任务依据已确认目标和选中事项生成，不把未选建议强塞进日程；这不等同已经实测用户能力或为所有任务建立独立技能评分。
5. 日安排先核对固定时段。当前支持当天正式未排任务与跨项目无日期待分配事项共同生成预览；待分配候选排除超出项目或事项截止范围的条目，最多取 100 项。建议标出来源，用户可以选择「本次不安排」。只有确认的候选才从池中移出并获得该日时段；未选项继续留池。含待分配项的批次遇到冲突、候选失效或预算不足时回滚并重新核对，不重复写入。重复固定学习计划仍要另行确认频率、有效日期、冲突与预览，不假定一句话已经生成永久规则。

描述执行结果时明确使用以下状态：建议、已生成预览、待确认、已写入、失败、尚未验证。只有成功回读目标位置，才说已经写入。说明书、模型文本和架构图不能替代实际执行证据。

用户要求录屏时，可依次演示资料与目标、能力选择、差距补齐、排期确认、月历、日时段、知识库和复盘。未实际录制不说已经完成；模拟响应或示例数据明确标注，避免展示真实密钥和私人信息。

资料中完整 Agent OS、Obsidian、外部群消息采集、后台自动执行和赛事效果均不能由这份 Skill 自行承诺。按用户已确定的工作台范围解释能力。
